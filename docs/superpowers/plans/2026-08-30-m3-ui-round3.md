## 主線程裁決（實作照此執行，不重議）

- **D1 /explore 資料架構**：新增 `ExploreIndex`（背景建置、原子換版）。候選池＝stats-data
  month 窗依 **roi 降冪** 取 top-N（`EXPLORE_CANDIDATE_POOL`，預設 100；排除 Filet 自營 leader 地址）。
  逐地址 enrich：`portfolio`（perpMonth 淨值曲線→sparkline＋30D 報酬＋30D 最大回撤；perpAllTime→交易日）＋
  `get_user_fills`（近 30D、上限一批→筆數/結倉勝率/幣種集中度/主要幣種）＋
  `clearinghouse_state`（帳戶規模 bucket＋目前曝險多空%）。enrich 序列執行、批間 sleep（保護 HL 額度，
  與實盤引擎共用——**沿用既有 ratelimit/負面快取，勿移除**）。index TTL 10min；建置完成前 endpoint 回
  `building: true`＋空 rows（前端顯示 R2·C 態二）。資格過濾與排序**全在後端**（R2-01）。
- **D2 指標定義（寫進 methodology、前端 tooltip 可引用）**：
  - 30D 報酬率＝perpMonth accountValueHistory 首末點變化率；帳戶淨值途中歸零或首點≤0 → 該列剔除。
  - 最大回撤＝perpMonth accountValueHistory running-peak 最深跌幅（顯式公式：`min_t(V_t/max_{s≤t}V_s - 1)`）。
  - 交易日＝perpAllTime accountValueHistory 的 distinct UTC 日數。
  - 結倉勝率＝近 30D fills 中 `closedPnl>0` 的結倉 fill 數 ÷ `closedPnl≠0` 的結倉 fill 數；值域外（<0 或 >100%）
    視為資料錯誤顯示「—」（R2-02）。
  - 集中度＝近 30D fills 成交額最大幣種佔比；>90% 標「集中度高」並被預設過濾排除。
  - 風險調整排序鍵＝30D 報酬率 ÷ |30D 最大回撤|（回撤為 0 時以 0.5% 下限代入，避免除零霸榜）。
- **D3 門檻進 config**（`EXPLORE_MIN_TRADING_DAYS=60`、`EXPLORE_MIN_FILLS=200`、
  `EXPLORE_MAX_DRAWDOWN_PCT=30`、`EXPLORE_MAX_COIN_CONCENTRATION_PCT=90`、`EXPLORE_PAGE_SIZE=25`），
  環境變數可覆寫，不寫死（R2-01）。
- **D4 路由**：新頁 `/explore`；`/leaderboard` 301/redirect 到 `/explore`（舊連結不斷）。
  nav：未登入 策略/探索/運作方式/安全性；登入後 Dashboard/策略/探索/設定（管理員項不動）。
- **D5 數字一致性**：策略卡（首頁＋/strategies 列表）與詳情頁同一支後端計算
  （filet.leader_perf 的 build_metrics），列表 endpoint 回傳與詳情相同欄位子集＋同一 `as_of` 時間戳；
  前端刪除 `strategyMetrics.ts` 的自算（CAGR 等一律由後端供給或不顯示）。回撤改名：
  策略頁「策略期間回撤」、Dashboard「你的跟單回撤」（copy.ts 兩個不同 key）。
- **D6 CSV 匯出**：前端由已載入資料產 CSV（client-side Blob），不加後端 endpoint。
- **D7 同步誤差 0ms 假數據**：後端 sync 塊在無樣本時送 `null` 而非 0；前端三態渲染，整卡無資料時摺為一行。
- **D8 探索榜不含 Filet 自營**（R2-04）：排除清單＝精選白名單 leaders 的地址集合，後端過濾。
- **D9 「跟單 →」**：`/advanced?leader=<address>`，advanced 頁讀 query 預填地址，風險勾選照舊。
- **D10 display_name**：stats-data 有 displayName 就顯示（上游任填值——僅展示，不做信任依據），
  無則縮寫地址；一鍵複製完整地址（R2-06）。ENS 解析不做（無現成依賴，backlog）。
- **D14（Task 4 實作後裁決，2026-08-30）**：ExploreRow 的 `tags` 與 `exposure.dir` 由中文字面值改為
  locale 中性代碼（`low_drawdown`/`concentrated`；`long`/`short`），前端經 copy.ts 對映顯示——
  API 契約不得內嵌單一語言的展示字串。其餘 Task 4 自行決策（redirect 沿用 /leaders 模式、
  過期 leaderboard copy 區塊暫留、pageStates 路由表補列）追認。
- **D11（Task 1 實作後追認，2026-08-30）**：builder 自行決策全數追認——`label`＝displayName 或縮寫地址；
  qualify 三個獨立布林開關對應三顆過濾 chip；門檻等號慣例＝下限 `>=`、上限 `<=`（測試釘死）；
  tag 在 `_apply_tags` 全批次計算；帳戶規模 bucket＝`<$10K / $10K–$100K / $100K–$1M / $1M+`
  （設計稿的 $10k–50k 等只是樣本數據非規格，整數邊界較穩）；`ExploreConfig.from_env()` 留在
  hl_explore.py；Filet 排除集＝精選白名單全部地址（含 disabled，偏保守方向正確）。

## Task 2b @inline：pnl_share_pct 同源實作＋午夜邊界修正（Task 2 追加裁決）

**背景（2026-08-30 主線程裁決 D12/D13）**：Task 2 builder 正確指出 HL 滾動窗（perpMonth 等）與
日曆期間費用分子不同基準，不可混用——追認。但「佔淨 PnL」是設計 R2·B 的核心訴求（NOTE 16
「讓成本可被感受」），不可永遠 null。修法：**分母改用與費用聚合同一條 fills 流**算
「期間已實現淨 PnL」＝ Σ closedPnl − Σ fees（同窗、同源、同基準）；語意如實改名
「佔已實現淨 PnL」（前端 copy key 同步，Task 5 引用）。未實現 PnL 明確不進分母（誠實標注優於好看）。

**需求：**
1. 若 fills 解析型別（UserFill 或 collect_follower_summary 所用 record）缺 `closedPnl`：
   **只做加法擴充**（optional 欄位，預設 None），不改任何引擎路徑行為；解析測試釘死
   「有 closedPnl 就帶出、沒有不炸」。
2. `pnl_share_pct` ＝ builder_fees ÷ 期間已實現淨 PnL；分母 ≤0 或無資料 → null。
   數值錨例進測試（顯式數字，如 fee 2.00、closedPnl 合計 10.00、fees 合計 3.50 →
   淨 6.50 → share ≈ 30.77%）。
3. 午夜邊界：逐日聚合改半開區間 `[day, day+1)`（fetch 後過濾 `t < end`），
   釘死「成交恰在 UTC 午夜」只入當日不入前日的測試。此為既有 `_dashboard_fees_month`
   舊病，一併修正；若 `/api/me/fills` 共用同一 helper，行為變更在回報中說明。

**驗收：** 同 Task 2（`uv run pytest -q -k "fees or dashboard"`、全量、ruff）。

**實作後追認（2026-08-30）**：`end_exclusive` 亦套用於期間總量呼叫（非僅逐日），否則逐日加總
對不上總量——追認。`collect_follower_summary` 預設 False 不動舊路徑（/api/ops/revenue 不受影響）。
UserFill.closed_pnl 為 optional 加法擴充，兩個 adapter（publicapi/hl.py、exchange/hyperliquid.py）
解析 closedPnl，缺欄/null → None（與顯式 0 區分）。
