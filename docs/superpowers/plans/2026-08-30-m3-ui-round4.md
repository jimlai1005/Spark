### Task R4-1 @inline：同步誤差改鏈上即時計算（後端）＋費用明細空日過濾

**Files:** `src/spark/publicapi/app.py`（_dashboard_sync 重寫、fees 逐日供給處）、
`src/spark/publicapi/ops.py`（若需小幅調整純函式介面）、tests。

**規格：**
1. `_dashboard_sync`：請求時直接向 HL 抓 **leader 與 follower 近 24h fills**
   （`userFillsByTime`；⚠️ 工程原則事故 #5：此端點回**所有 dex**的成交——兩側都要
   以同一涵蓋範圍比較，如需過濾以 fill 的 coin/dex 欄位對稱過濾，兩側同規則）＋
   雙方 `clearinghouseState`，餵既有 `follower_trade_quality` 純函式（或其等價組裝）
   計算：訊號延遲中位/p95（leader fill ↔ follower fill 依 coin/方向/時間鄰近配對）、
   加權成交價差 bp、遺漏訊號數（leader 有、follower 24h 內無對應）、未同步倉位數與
   部位比例偏差（兩側當前持倉 × follower scale 對比）。
   - **零落盤**：不寫任何檔案；可用 in-memory TTLCache（60s，now_fn 注入）。
   - `last_recon_ts` 改為本次計算時刻（欄位語義改「本次鏈上比對時刻」）；引擎本機
     對帳時戳不再出現。scale（投入比例）讀既有 capital effective（心跳）可得則用，
     不可得 → 偏差欄 null。配對不到／資料不足的欄位照舊 null，不造數。
   - leader 地址來源：me/leader（session）；未跟單 → sync 塊整塊 null。
2. fees 逐日：`/api/me/fees`（與 dashboard fees_month.daily_bars）只回**有成交或有費用**
   的日期（`fill_count>0 or builder_fee>0`）；合計欄位不變。
3. 測試：假 fills 注入的配對/延遲/價差錨例（手算一組寫死）；空 fills → 全 null 不 500；
   fills 快取 60s 內上游只叫一次；daily 過濾（3 天有值 2 天空 → 只回 3 筆）。

**驗收：** `uv run pytest -q` 全綠＋ruff 乾淨；`grep -n "warming\|24h 內開始累積" src/spark | wc -l` 為 0（後端無此概念）。
